Scores, eligibility & diagnosticssrc/nwb/scoring.py

Aggregation reads retained files without requesting model answers. Core ranks use 13 visual item scores; Nai-hub ranks use seven-field joint accuracy. Standard generation has a separate 30-cell rank. Text, blind controls and optional state tasks stay diagnostic.

External calls happen through the backend adapters. Report, snapshot, export and release processing are local.

13Core visual items9 LLM-judged recognition items + 4 locally keyed grounding checks. Eight text diagnostics and four blind controls sit outside the rank.
24Nai-hub visual itemsSeven fields per image, scored locally. All seven correct = 100; otherwise 0. Twenty-four matched blind controls are diagnostic.
30Generation cellsSix default animals × five tiers. LLM judges rate weighted style and animal identity. Overall = style × identity / 2.
A score becomes a rank only after eligibility checks
  • Every required cell is scored with the same attempted repetition IDs.
  • Recorded settings agree across the panel; alternate-route fills remain diagnostic.
  • Subject and judge prompts are current; judgment target identity matches.
  • Tool-contaminated understanding answers are excluded.
  • Generation prompts have a verified verbatim audit. Verified provider refusals score zero.
Judge selectionOther-vendor judgments take precedence. Available judges are used when none are independent. Reports disclose the contributing panel.
Optional state transferCore: 3 sources, 6 extraction/control tasks, 12 default generation requests. Nai-hub: 8 sources, 16 extraction/control tasks, 32 requests. Generated transfers are unscored.

The two rankings are independent. Nai-hub keys are provisional Astra annotations. Bootstrap intervals describe sensitivity to the selected source images/animals and fixed judges.

01

Collection, judging or reporting completes.
The CLI refreshes the run's snapshot. --no-sync keeps an experiment local. nwb sync saves an existing run explicitly.

02

Normal Git commit and push includes results/.
The CLI updates files. Git synchronization is an explicit repository operation. Unchanged image content reuses Git blobs; attributes preserve hashed bytes.

03

A fresh checkout restores a missing working run.
Checksums and suite membership are verified before copying saved files into runs/. Existing working runs take precedence.

04

nwb release --manifest releases/0.1.0.toml
The manifest selects each suite's run, normalized input digest and judges. The builder rejects changed inputs and stale judgments, then builds both pages and raw bundles offline.

05

Explicit site publication
scripts/publish_site.sh MANIFEST rebuilds in a fresh directory and pushes generated output to gh-pages. Source merging and site publication are separate operations.
