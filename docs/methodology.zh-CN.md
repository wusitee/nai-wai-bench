# 评测方法

[English](methodology.md) | 简体中文 | [繁體中文](methodology.zh-Hant.md)

这是一个小型的领域基准，考察对 大笑奶龙 / 奶蛙 的了解、识别以及把它的风格迁移到动物身上的能力。它不是
通用智能或通用图像质量的基准。两个暂定的看图理解排名，识梗 Meme ID 和看图 Visual detail，合成为
[奶蛙指数](#奶蛙指数)；图像生成是不计入指数的实验排名。已实现的计分和题目覆盖规则见
[design.zh-CN.md](design.zh-CN.md)。

## 研究依据

以下是对成熟评测原则的借鉴，并非对所引基准的复现，也不声称达到同等的效度验证。

| 主要来源 | 可借鉴的原则 | 在本基准中的应用 |
|---|---|---|
| [GenEval (2023)](https://arxiv.org/abs/2310.11513) | 分别评估不同的视觉属性，而不是只用一个整体相似度分数 | 分别给姿势、表情、渲染和动物辨识度打分；公布各特征和各动物的诊断结果 |
| [TIFA (2023)](https://arxiv.org/abs/2303.11897) | 把忠实度拆解成可回答的视觉问题 | 视觉核对题有明确的姿势／眼睛答案键；生成图评审根据可见证据逐项评估特征 |
| [GenEval 2 (2025)](https://github.com/facebookresearch/GenEval2) | 扩大概念覆盖面，并核查评估器的分数是否仍与人的判断一致 | 使用六种身体结构各异的动物，保留可供查看的图片和评审理由；下文的方案要求做一次小规模人工核查 |
| [MMStar (2024)](https://arxiv.org/abs/2403.20330) | 检查题目是否真的需要图片，把视觉带来的收益与语言先验区分开 | 对不同图片提出完全相同的视觉核对问题，并为每张图设置一个不给图的配对对照 |
| [MMBench (2024 修订版)](https://arxiv.org/abs/2307.06281) | 中英文题目一一对应，并检查对选项的敏感度 | 知识、视觉记忆和提示词写作题在两种语言间一一对应；用语义化的 JSON 标签代替字母选项位置 |

本评测程序没有实现 GenEval 的检测器、TIFA 的问题生成流程、GenEval 2 的 Soft-TIFA 概率、MMStar 的训练
泄漏测量，也没有实现 MMBench 的 CircularEval。对于这个小语料库，它们完整的流程并无必要，而且可能需要多得多
的推理调用或本地模型。固定答案键不需要评估模型；现有以原图为依据的特征评审也无需引入庞大的评测体系即可
供人查看。

## 各排名衡量什么

**图像生成**（实验）使用六种动物和五个提示词档位：每个模型 30 格。猫和熊猫考察熟悉的哺乳动物形象；青蛙检验这个
梗与两栖动物的联系；长颈鹿和章鱼考验把姿势迁移到不同身体结构上的能力；大象考察有辨识度的耳朵和鼻子。这是
一个有针对性的小题组，并非动物的代表性样本。五个档位区分了给出名称、给出描述和给出参考图时的表现。它们的
均分衡量的是各种提示条件下完成这个梗任务的表现，因此比较“凭名称回忆”和“借助参考图迁移”时，请查看各档位
的分数。

**视觉理解**（识梗）使用九道识别题和四道视觉核对题。识别题包括两种语言下的原图、一张动物二创图、流传的变体，以及
作为阴性对照的官方形象图。这些题目把视觉证据和文化知识结合起来。四道视觉核对题对四张不同的图片提出相同的
姿势和眼睛状态问题，答案键只包含可以直接观察到的属性。它们考察的是基础感知，而不是困难的视觉推理。13 道题
权重相同；原图特意考了两次，用于中英文双语识别的对照。这些公开图片在多道题中重复使用，因此 13 道题并不等于
13 个相互独立的视觉样本。

**文字／语言诊断** 每种语言使用四道一一对应的题目：知识、凭记忆描述画面，以及为猫和长颈鹿写提示词。各语言
版本使用相同的检查项清单。语言均分不含无图对照，比较时必须保证题目覆盖和评审组相同。英文提示词写作题的回答
本身可以使用别的语言：这些题目衡量的是对输入语言的理解，而不是严格遵守输出语言。生成档位并不是完全对应的
翻译实验，因此它们之间的差异不能单独归因于语言。

**无图对照** 重复四道视觉核对题的提示词，但不提供图片。计算视觉增益前，先按题目和重复编号配对。拒答和
`unknown` 在两种条件下都不得分，所以增益也取决于模型是否愿意猜测以及是否遵循指令；它是关于本任务对图片依赖
程度的证据，而不是对视觉能力的纯粹度量。一个总是回答“睁眼”的模型在眼睛这一项上已经能得 75%；核查时请分别
报告姿势和眼睛的回答，不要假设总分的随机基线是 50%。

## 奶蛙指数

发布版本用**奶蛙指数 · NaiWai Index** 排名，即两个看图排名的加权平均：

    指数 = (识梗得分 + 2 × 看图得分) / 3

只有两项都有名次（在同一设置下完整、均衡地跑完题组）的模型才有指数名次，其余标为 partial。看图的权重加倍，
因为它的题组更大（24 张图对 13 道题），并且完全按本地答案键计分；识梗还考察文化知识、梗名和别名，但 13 道题
中有 9 道依赖同一个 LLM 评审，而在选定的对比中该评审也给同厂商的模型打分。每种推理强度配置各占一行。

两项使用不同的指标：识梗逐题给部分分，看图要求七项全对。两者的尺度没有相互校准，所以指数只用于在本基准上
排序，不是正确率。指数旁同时列出两项的得分和名次，因为两种能力会分化：一个模型可能在一项中名列前茅，在另一项
中却排在末尾。

区间和名次范围把两项各自的 2,000 次聚类自助重抽样按序号配对后加权。这把两项视为相互独立的样本，尽管看图有
5 张图片复用了识梗的素材（其中一张为裁切）。看图的答案键由 GPT-6-Astra 标注、尚待人工校验，所以 Astra 的指数也包含与自己标注的
一致程度；网站会标出这一点。

指数的定义带版本号（`index.json` 记录版本和权重）。更换组成题组（例如以新题组 id 发布经过校验的答案键）或修改
权重都会产生新的指数版本，不同版本的分数不可比较。

## 受限的评测预算

先对每个模型在整个题组上各跑一次。覆盖全面且一一对应，比反复跑很多次猫更有用。下表的调用次数不含失败的调用，
也不含评审允许的那一次重试。

| 每个被测模型的工作量 | 一次重复所需的调用 |
|---|---:|
| 生成题组 | 30 次图像生成请求 |
| 用默认的 Opus 评审评审生成图 | 30 次视觉评审请求 |
| 视觉理解 | 13 次回答请求 |
| 文字／语言诊断 | 8 次回答请求 |
| 无图对照 | 4 次回答请求 |
| 用默认的 Opus 评审评审全部自由作答的理解题 | 17 次评审请求 |
| 评审视觉核对题及其对照 | 0 |

两部分的默认评审都只有 Claude Opus 5.5，Anthropic 的被测模型也由它评审。所有被测模型应使用同一组已配置的
评审，并记录下来。显式选择多个评审时，优先计入其他厂商的评审；只有没有独立评审时，才计入同厂商的评审。
report、site、export 和结果快照按已配置的评审计分，除非用 `--judges` 另行指定；`nwb judge --judges` 只决定
调用哪些评审。已发布的比较沿用发布清单中固定的评审选择。评审健康度是用来诊断分歧的，既不能证明评估器正确，也不能仅因为某个评审改变了排序就把它剔除。应在
比较被测模型的分数之前，用固定的校准样例决定排除哪些评审。

```sh
# 低成本的视觉依赖诊断：四次看图输入 + 四个无图对照，不需要评审调用。
uv run nwb understand --run pilot --models MODEL --items grounding
uv run nwb report --run pilot

# 完整、可比较的题组；understand 也会收集文字诊断和无图对照。
uv run nwb understand --run comparison --models VISION_MODEL
uv run nwb imagegen --run comparison --models IMAGE_MODEL --animals default
uv run nwb judge --run comparison
uv run nwb report --run comparison
uv run nwb site --run comparison
```

请把命令中的名称替换为 `nwb list` 中已配置的模型名。没有视觉能力的模型可以跑文字诊断和无图对照，但无法填满
视觉排名题组。如果只需要视觉题组，`--items vision` 会省略文字诊断和对照。report／site 的 `--judges` 只改变
哪些已记录的评审结果计入，不会发起模型请求。

## 发布方案与局限

1. 在收集比较数据之前，冻结题目文件、评分标准、参考素材、模型版本、调用设置、重复次数和评审组。导出结果时
   保留仓库的版本号。改动默认动物集合或必需的看图题会改变题组，需要重新比较。
2. 跑完每个必需的格子。基础设施错误可以重试，但不能在多个成功的输出之间挑选。服务商的安全系统拒绝原样
   提示词属于结果，记 0 分且不重试。调用了工具的回答，以及提示词未核实或被改动的生成样本，都不具备排名资格。
   评测程序会检查提示词是否一致、样本是否最新，但无法保证厂商隐藏的设置完全相同。
3. 发布前检查一个小的固定核查集：四张视觉核对题的原图、作为阴性对照的官方形象图，以及每个图像模型的同样
   六个生成格（每种默认动物一格，档位事先选定）。人工核查时隐藏模型和厂商标签。校准评审时加入故意画错姿势或
   动物的样例。记录分歧；看到排名后不要悄悄修改分数。评测程序会提供这些输出供核查，但不会自动完成或认证
   人工校准。
4. 连同名次一起公布题组覆盖情况、重复次数、各档位分数、提示词核对结果、实际参与的评审、文字／无图诊断，
   以及配对聚类自助法区间和名次范围。若排序需要更多支撑，让所有相互竞争的模型在完整题组上各多跑一次相同的
   重复，不要挑选表现差的格子重跑。区间只描述小题组的敏感度，不是显著性检验或总体结论。

素材是公开的，语料库很小，部分识别题的图片是合成的。当前图片使用中性文件名，历史运行可能暴露原始文件名。本基准不声称有未受污染
的保留集，也不保证输入是盲的。答对基础视觉核对题，不代表了解这个梗的历史；把来龙去脉讲得头头是道，也不代表
模型用到了输入的图片。加权特征分也保留了主观选择，尤其是 `vibe`（整体气质）这一项。知识比率是配对的提示词
敏感度诊断，可能大于 1，不能说明训练数据中是否见过这个梗。token、图片和延迟方面的成本取决于所配置的服务商；
上面的调用次数是规划预算，不是实测账单，也不是新的基准结果。

## 不确定性与效率

合格排名使用固定种子 6643 的 2,000 次聚类自助重抽样，显示 95% 分数区间和整数名次范围。
同一格的重复先取均值，再对原图（理解）或包含五档的动物（生成）重抽样；所有模型共享同一次抽样。
区间以观察到的重复和固定评审为条件，不量化答案键或评审的不确定性，也不支持显著性或总体性能结论。
看图题组的重复一致性统计至少有两次回答的图片中，各次“七项全对”判定相同的比例，持续答错也算一致。

效率诊断显示视觉题组的 token 覆盖率、已报告 token 均值、客户端耗时中位数和 API 标价估计，
缺失值保持未知。订阅 CLI 不按 token 计费，客户端耗时也不是模型速度。完整的抽样、缓存计价和
被测模型／评审资源分账规则见[英文说明](methodology.md#uncertainty-and-efficiency)。

## 跨动物的表情迁移

这个可选题组测试的是源图的表情能否迁移到另一种动物身上，而不仅仅是生成器能否重现经典的大笑。三种源表情是
愤怒、扶额和得意，默认的小目标题组是猫和青蛙。这些是针对所选素材、按可见表情／动作划分的类别，而不是通用的
或心理学意义上的情绪分类。

对每个表情／动物组合，比较 **参考图迁移** 和 **固定描述生成**。参考图条件提供源图和一条与表情无关的相同
指令；描述条件不给图片，而是给出明确的可见特征。源图的身体颜色不是成功标准：动物保留自己的颜色和花纹，所以
仅仅画出一只红色动物不能算作“愤怒”迁移成功。对于裁切过的特写，应保持取景，不要在画面外凭空添加动作。

愤怒源图去掉了文字和表情符号，三张附图都使用中性的文件名。否则，表情提取模型可能直接根据「切换愤怒模式」或
文件名作答，而不是看角色本身。素材出处和固定的裁切方式见 [SOURCE.md](../bench/reference/SOURCE.md)。

视觉理解题分别提取表情、眼睛、嘴巴和动作，对每张源图使用相同的提示词，并附带一个无图对照。在本地按答案键
匹配，每个模型一次重复只需 **六次被测调用、零次评审调用**。这些回答只作诊断：生成使用固定描述，所以上游的
提取错误不会悄悄改变交给不同图像生成器的任务。各字段并不均衡（三张图的嘴巴都是闭着的），所以不要假设一个
通用的随机基线分数；请查看各个字段和配对的无图对照。两种生成条件合计每个生成器 **12 次图像请求**，不会扩大
默认题组。

生成结果需要人工查看；不使用 LLM 评审，也不套用经典大笑的评分。在隐藏模型和厂商标签的情况下，对同一表情／
动物组合比较两种条件。判定迁移成功之前，分别记录以下标准：

1. **动物辨识度：** 能从有意义的特征认出目标物种，而不是在红色或黄色的奶龙身体上加一对象征性的耳朵。
2. **表情：** 可见的眼睛、眉毛和嘴巴传达出源图的表情。泛泛的开心，或者退回到经典的张嘴大笑，对这三种表情
   都算失败。
3. **动作／姿态：** 可见时保留扶额或手背在身后的姿态。对于得意的特写，检查半睁的眼睛和抬起的下巴；不要要求
   画面外并不存在的手。
4. **风格：** 保持光滑、敦实的 3D 梗图渲染。与表情是否正确分开报告。

只有同时具备可辨认的动物形象、源图的表情以及任何可见的动作／姿态，才算整体迁移成功。风格单独查看，这样画得
精致也无法弥补表情错误。按表情、动物和条件分别公布观察结果；不要把这个很小的可选题组并入两个核心排名。参考图
条件表现更好，说明在这些例子上视觉条件输入有用，但不能证明模型具备通用的情绪理解能力。每种表情只有一张源图，
因此表情、源图画风和视角是混在一起的。在作出更广泛的迁移结论之前，请为每种表情再加一张独立来源的样例。

评测程序不会合成任何人工评分。在收集到人工评审之前，生成图库没有迁移准确率分数，预先定义的提取标签也仍是
暂定的。
