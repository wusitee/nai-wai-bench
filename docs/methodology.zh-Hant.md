# 評測方法

[English](methodology.md) | [简体中文](methodology.zh-CN.md) | 繁體中文

這是一個小型的領域基準，考察對 大笑奶龍 / 奶蛙 的了解、識別以及把它的風格遷移到動物身上的能力。它不是
通用智能或通用圖像品質的基準。它的兩個暫定排名分別獨立衡量圖像生成和視覺理解。已實作的計分和題目涵蓋
規則見 [design.zh-Hant.md](design.zh-Hant.md)。

## 研究依據

以下是對成熟評測原則的借鑑，並非對所引基準的重現，也不聲稱達到同等的效度驗證。

| 主要來源 | 可借鑑的原則 | 在本基準中的應用 |
|---|---|---|
| [GenEval (2023)](https://arxiv.org/abs/2310.11513) | 分別評估不同的視覺屬性，而不是只用一個整體相似度分數 | 分別為姿勢、表情、渲染和動物辨識度評分；公佈各特徵和各動物的診斷結果 |
| [TIFA (2023)](https://arxiv.org/abs/2303.11897) | 把忠實度拆解成可回答的視覺問題 | 視覺核對題有明確的姿勢／眼睛答案鍵；生成圖評審根據可見證據逐項評估特徵 |
| [GenEval 2 (2025)](https://github.com/facebookresearch/GenEval2) | 擴大概念涵蓋面，並核查評估器的分數是否仍與人的判斷一致 | 使用六種身體結構各異的動物，保留可供檢視的圖片和評審理由；下文的方案要求做一次小規模人工核查 |
| [MMStar (2024)](https://arxiv.org/abs/2403.20330) | 檢查題目是否真的需要圖片，把視覺帶來的收益與語言先驗區分開 | 對不同圖片提出完全相同的視覺核對問題，並為每張圖設置一個不給圖的配對對照 |
| [MMBench (2024 修訂版)](https://arxiv.org/abs/2307.06281) | 中英文題目一一對應，並檢查對選項的敏感度 | 知識、視覺記憶和提示詞撰寫題在兩種語言間一一對應；用語義化的 JSON 標籤取代字母選項位置 |

本評測程式沒有實作 GenEval 的偵測器、TIFA 的問題生成流程、GenEval 2 的 Soft-TIFA 機率、MMStar 的訓練
洩漏測量，也沒有實作 MMBench 的 CircularEval。對於這個小語料庫，它們完整的流程並無必要，而且可能需要多得多
的推論呼叫或本地模型。固定答案鍵不需要評估模型；現有以原圖為依據的特徵評審也無需引入龐大的評測體系即可
供人檢視。

## 兩個排名衡量甚麼

**圖像生成** 使用六種動物和五個提示詞檔位：每個模型 30 格。貓和熊貓考察熟悉的哺乳動物形象；青蛙檢驗這個
迷因與兩棲動物的聯繫；長頸鹿和章魚考驗把姿勢遷移到不同身體結構上的能力；大象考察有辨識度的耳朵和象鼻。這是
一個有針對性的小題組，並非動物的代表性樣本。五個檔位區分了給出名稱、給出描述和給出參考圖時的表現。它們的
平均分衡量的是各種提示條件下完成這個迷因任務的表現，因此比較「憑名稱回憶」和「借助參考圖遷移」時，請查看
各檔位的分數。

**視覺理解** 使用九道識別題和四道視覺核對題。識別題包括兩種語言下的原圖、一張動物二創圖、流傳的變體，以及
作為陰性對照的官方形象圖。這些題目把視覺證據和文化知識結合起來。四道視覺核對題對四張不同的圖片提出相同的
姿勢和眼睛狀態問題，答案鍵只包含可以直接觀察到的屬性。它們考察的是基礎感知，而不是困難的視覺推理。13 道題
權重相同；原圖特意考了兩次，用於中英文雙語識別的對照。這些公開圖片在多道題中重複使用，因此 13 道題並不等於
13 個互相獨立的視覺樣本。

**文字／語言診斷** 每種語言使用四道一一對應的題目：知識、憑記憶描述畫面，以及為貓和長頸鹿撰寫提示詞。各語言
版本使用相同的檢查項清單。語言平均分不含無圖對照，比較時必須確保題目涵蓋和評審組相同。英文提示詞撰寫題的
回答本身可以使用別的語言：這些題目衡量的是對輸入語言的理解，而不是嚴格遵守輸出語言。生成檔位並不是完全
對應的翻譯實驗，因此它們之間的差異不能單獨歸因於語言。

**無圖對照** 重複四道視覺核對題的提示詞，但不提供圖片。計算視覺增益前，先按題目和重複編號配對。拒答和
`unknown` 在兩種條件下都不得分，所以增益也取決於模型是否願意猜測以及是否遵循指示；它是關於本任務對圖片依賴
程度的證據，而不是對視覺能力的純粹度量。一個總是回答「睜眼」的模型在眼睛這一項上已經能得 75%；核查時請分別
回報姿勢和眼睛的回答，不要假設總分的隨機基線是 50%。

## 受限的評測預算

先對每個模型在整個題組上各跑一次。涵蓋全面且一一對應，比反覆跑很多次貓更有用。下表的呼叫次數不含失敗的呼叫，
也不含評審允許的那一次重試。

| 每個受測模型的工作量 | 一次重複所需的呼叫 |
|---|---:|
| 生成題組 | 30 次圖像生成請求 |
| 用兩個已設定的評審評審生成圖 | 60 次視覺評審請求 |
| 視覺理解 | 13 次回答請求 |
| 文字／語言診斷 | 8 次回答請求 |
| 無圖對照 | 4 次回答請求 |
| 用兩個具備視覺能力的評審評審全部自由作答的理解題 | 34 次評審請求 |
| 評審視覺核對題及其對照 | 0 |

設定兩個評審並不保證得到兩份獨立評審：如果受測模型與其中一個評審同屬一家廠商，就只有另一個評審的分數計入。
所有受測模型應使用同一組已設定的評審，並記錄下來。要讓每個受測模型都有兩家獨立廠商的評審，可能需要三家廠商
的評審。評審健康度是用來診斷分歧的，既不能證明評估器正確，也不能僅因為某個評審改變了排序就把它剔除。應在
比較受測模型的分數之前，用固定的校準樣例決定排除哪些評審。

```sh
# 低成本的視覺依賴診斷：四次看圖輸入 + 四個無圖對照，不需要評審呼叫。
uv run nwb understand --run pilot --models MODEL --items grounding
uv run nwb report --run pilot

# 完整、可比較的題組；understand 也會收集文字診斷和無圖對照。
uv run nwb understand --run comparison --models VISION_MODEL
uv run nwb imagegen --run comparison --models IMAGE_MODEL --animals default
uv run nwb judge --run comparison --judges VISION_JUDGE_A,VISION_JUDGE_B
uv run nwb report --run comparison
uv run nwb site --run comparison
```

請把命令中的名稱替換為 `nwb list` 中已設定的模型名稱。沒有視覺能力的模型可以跑文字診斷和無圖對照，但無法
填滿視覺排名題組。如果只需要視覺題組，`--items vision` 會省略文字診斷和對照。report／site 的 `--judges` 只
改變哪些已記錄的評審結果計入，不會發起模型請求。

## 發佈方案與局限

1. 在收集比較資料之前，凍結題目檔案、評分標準、參考素材、模型版本、呼叫設定、重複次數和評審組。匯出結果時
   保留儲存庫的版本號。改動預設動物集合或必需的看圖題會改變題組，需要重新比較。
2. 跑完每個必需的格子。基礎設施錯誤可以重試，但不能在多個成功的輸出之間挑選。服務商的安全系統拒絕原樣
   提示詞屬於結果，記 0 分且不重試。呼叫了工具的回答，以及提示詞未核實或被改動的生成樣本，都不具備排名
   資格。評測程式會檢查提示詞是否一致、樣本是否最新，但無法保證廠商隱藏的設定完全相同。
3. 發佈前檢查一個小的固定核查集：四張視覺核對題的原圖、作為陰性對照的官方形象圖，以及每個圖像模型的同樣
   六個生成格（每種預設動物一格，檔位事先選定）。人工核查時隱藏模型和廠商標籤。校準評審時加入故意畫錯姿勢或
   動物的樣例。記錄分歧；看到排名後不要悄悄修改分數。評測程式會提供這些輸出供核查，但不會自動完成或認證
   人工校準。
4. 連同名次一起公佈題組涵蓋情況、重複次數、各檔位分數、提示詞核對結果、評審選擇，以及文字／無圖診斷。評測
   程式只顯示觀察到的暫定名次，不計算信賴區間或顯著性檢定。如果某個重要的排序需要更多支撐，請把剩餘預算用於
   讓所有互相競爭的模型在完整題組上各多跑一次相同的重複，而不是挑選表現差的格子重跑。後續做統計分析時，比較
   模型間的配對差異，並按原圖或動物重抽樣，把翻譯、檔位和重複保留在各自的組內。四到六個組給出的不確定性估計
   仍然很弱；避免作出強的總體性結論。

素材是公開的，語料庫很小，部分識別題的圖片是合成的，Agent 用戶端也可能暴露原始檔名。本基準不聲稱有未受污染
的保留集，也不保證輸入是盲的。答對基礎視覺核對題，不代表了解這個迷因的歷史；把來龍去脈講得頭頭是道，也不
代表模型用到了輸入的圖片。加權特徵分也保留了主觀選擇，尤其是 `vibe`（整體氣質）這一項。知識比率是配對的
提示詞敏感度診斷，可能大於 1，不能說明訓練資料中是否見過這個迷因。token、圖片和延遲方面的成本取決於所設定
的服務商；上面的呼叫次數是規劃預算，不是實測帳單，也不是新的基準結果。

## 跨動物的表情遷移

這個可選題組測試的是來源圖的表情能否遷移到另一種動物身上，而不僅僅是生成器能否重現經典的大笑。三種來源
表情是憤怒、扶額和得意，預設的小目標題組是貓和青蛙。這些是針對所選素材、按可見表情／動作劃分的類別，而不是
通用的或心理學意義上的情緒分類。

對每個表情／動物組合，比較 **參考圖遷移** 和 **固定描述生成**。參考圖條件提供來源圖和一條與表情無關的相同
指示；描述條件不給圖片，而是給出明確的可見特徵。來源圖的身體顏色不是成功標準：動物保留自己的顏色和花紋，
所以僅僅畫出一隻紅色動物不能算作「憤怒」遷移成功。對於裁切過的特寫，應保持取景，不要在畫面外憑空加上動作。

憤怒來源圖去掉了文字和表情符號，三張附圖都使用中性的檔名。否則，表情提取模型可能直接根據「切換憤怒模式」或
檔名作答，而不是看角色本身。素材出處和固定的裁切方式見 [SOURCE.md](../bench/reference/SOURCE.md)。

視覺理解題分別提取表情、眼睛、嘴巴和動作，對每張來源圖使用相同的提示詞，並附帶一個無圖對照。在本地按答案鍵
比對，每個模型一次重複只需 **六次受測呼叫、零次評審呼叫**。這些回答只作診斷：生成使用固定描述，所以上游的
提取錯誤不會悄悄改變交給不同圖像生成器的任務。各欄位並不均衡（三張圖的嘴巴都是閉著的），所以不要假設一個
通用的隨機基線分數；請查看各個欄位和配對的無圖對照。兩種生成條件合計每個生成器 **12 次圖像請求**，不會擴大
預設題組。

生成結果需要人工檢視；不使用 LLM 評審，也不套用經典大笑的評分。在隱藏模型和廠商標籤的情況下，對同一表情／
動物組合比較兩種條件。判定遷移成功之前，分別記錄以下標準：

1. **動物辨識度：** 能從有意義的特徵認出目標物種，而不是在紅色或黃色的奶龍身體上加一對象徵性的耳朵。
2. **表情：** 可見的眼睛、眉毛和嘴巴傳達出來源圖的表情。泛泛的開心，或者退回到經典的張嘴大笑，對這三種表情
   都算失敗。
3. **動作／姿態：** 可見時保留扶額或手放在身後的姿態。對於得意的特寫，檢查半睜的眼睛和抬起的下巴；不要要求
   畫面外並不存在的手。
4. **風格：** 保持光滑、敦實的 3D 迷因圖渲染。與表情是否正確分開回報。

只有同時具備可辨認的動物形象、來源圖的表情以及任何可見的動作／姿態，才算整體遷移成功。風格單獨檢視，這樣畫得
精緻也無法彌補表情錯誤。按表情、動物和條件分別公佈觀察結果；不要把這個很小的可選題組併入兩個核心排名。參考圖
條件表現較好，表示在這些例子上視覺條件輸入有用，但不能證明模型具備通用的情緒理解能力。每種表情只有一張來源圖，
因此表情、來源圖畫風和視角是混在一起的。在作出更廣泛的遷移結論之前，請為每種表情再加一張獨立來源的樣例。

評測程式不會合成任何人工評分。在收集到人工評審之前，生成圖庫沒有遷移準確率分數，預先定義的提取標籤也仍是
暫定的。
